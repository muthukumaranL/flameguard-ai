# FlameGuard AI - runtime dependencies for the deployed Streamlit app.
#
# Streamlit Community Cloud installs from this file, so it stays lean: only what
# app.py imports at runtime. Analysis, export, document and test tooling lives in
# requirements-dev.txt, which scripts/setup_environment.sh (.bat) installs.
#
# torch/torchvision are intentionally NOT pinned here. ultralytics pulls them in,
# and the Cloud installed them without trouble. Pinning the +cpu wheels needs an
# --extra-index-url, which resolvers treat inconsistently (uv's default
# first-index strategy never reaches the extra index for a +cpu local version),
# so an explicit pin is more fragile here, not less. Locally,
# scripts/setup_environment.* installs the CUDA wheel before this file is read.

# Core inference
ultralytics>=8.3,<9
# ultralytics hard-requires opencv-python, whose cv2 links two libraries a bare
# container does not ship: libGL.so.1 and libgthread-2.0.so.0. packages.txt installs
# them as libgl1 and libglib2.0-0t64 - Streamlit Cloud runs Debian trixie, where the
# glib package carries the t64 suffix from the 64-bit time_t transition (the older
# name libglib2.0-0 does not resolve, and one unknown name fails the whole apt step).
# Keep packages.txt free of comments: the apt step can be fed through xargs, which
# would pass '#' and the comment words along as package names.
#
# On Linux we additionally install the headless build, listed last so it lands after
# opencv-python and provides a cv2 with no GL/X11 linkage at all - belt and braces if
# a further system library turns up missing. The marker keeps Windows on the full
# build, because the OpenCV desktop fallback (src/webcam_inference.py:119) calls
# cv2.imshow, which the headless build omits.
opencv-python>=4.10
opencv-python-headless>=4.10 ; sys_platform == "linux"
numpy>=2.0
pillow>=10.0
PyYAML>=6.0
pandas>=2.2

# Application
streamlit>=1.40
streamlit-webrtc>=0.62
av>=13.0
imageio-ffmpeg>=0.5
